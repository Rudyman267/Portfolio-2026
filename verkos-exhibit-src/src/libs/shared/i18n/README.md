# Internationalization (i18n) Setup

This module provides a centralized i18n configuration for the monorepo using `react-i18next` and `lingo.dev` for translation management.

## Features

- ✅ Centralized i18n configuration in shared library
- ✅ Static import of translations (bundled with Vite)
- ✅ Type-safe translation hooks
- ✅ Language detection and persistence
- ✅ Lingo.dev integration for translation management
- ✅ Environment-based configuration

## Usage

### 1. Setup in App

```tsx
// apps/your-app/src/App.tsx
import { I18nProvider } from '@cloud/shared';

export default function App() {
  return <I18nProvider>{/* Your app components */}</I18nProvider>;
}
```

### 2. Using Translations in Components

```tsx
// Any component
import { useTranslation } from '@cloud/shared';

export const MyComponent = () => {
  const { t } = useTranslation();

  return (
    <div>
      <h1>{t('greeting')}</h1>
    </div>
  );
};
```

### 3. Language Switching

```tsx
import { useLanguage } from '@cloud/shared';

export const LanguageSwitcher = () => {
  const { currentLanguage, supportedLanguages, changeLanguage } = useLanguage();

  return (
    <div>
      {supportedLanguages.map((lang) => (
        <button key={lang} onClick={() => changeLanguage(lang)} className={currentLanguage === lang ? 'active' : ''}>
          {lang.toUpperCase()}
        </button>
      ))}
    </div>
  );
};
```

## Configuration

### Lingo.dev Configuration

The root `i18n.json` file is configured to output translations to the shared library:

```json
{
  "version": 1.8,
  "locale": {
    "source": "en",
    "targets": ["es"]
  },
  "buckets": {
    "json": {
      "include": ["libs/shared/i18n/locales/[locale].json"]
    }
  }
}
```

### Custom Configuration

You can pass custom configuration to the I18nProvider:

```tsx
<I18nProvider
  config={{
    defaultLocale: 'en',
    supportedLocales: ['en', 'es', 'fr'],
    debug: true,
  }}
>
  {/* Your app */}
</I18nProvider>
```

## Adding New Languages

1. Add the language to lingo.dev targets in `i18n.json`
2. Generate translations using lingo.dev
3. Import the new language file in `libs/shared/i18n/i18n.ts`
4. Add to the `resources` object
5. Update the `SupportedLocale` type

## Development

- Translations are bundled at build time via Vite
- Changes to translation files trigger hot reloads
- Debug mode shows missing translations in console
- Language preference is persisted in cookies

## Production

- All translations are included in the app bundle
- No runtime fetching of translation files
- Optimized and minified by Vite
- Fallback to default language for missing keys
